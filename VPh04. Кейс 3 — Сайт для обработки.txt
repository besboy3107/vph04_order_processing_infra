VPh04. Кейс 3 — Сайт для обработки заказов. Часть 1 (инфраструктура)

Выполнено в Claude Code (CLI-агент от Anthropic, работает прямо в терминале) - вместо Cursor. Все действия - подключение к серверу по SSH, установка Docker, написание конфигов, деплой и выпуск TLS - выполнялись через Claude Code.

Репозиторий: https://github.com/besboy3107/vph04_order_processing_infra

Что сделано

1. Арендован VPS на Ubuntu, доступ по SSH-ключу (ed25519), авторизация по паролю отключена.
2. Установлен Docker + плагин docker compose.
3. Развёрнута инфраструктура «докеризированного монолита» через docker-compose.yml с 5 сервисами:
  - Nginx - единственная точка входа, отдаёт фронт и проксирует /pgadmin/;
  - PostgreSQL 16 - внутренняя БД, наружу порт не публикуется (expose), доступ только внутри сети;
  - pgAdmin - панель управления БД в server-режиме (с логином), доступна через Nginx;
  - Docker Registry - приватный реестр образов с Basic Auth;
  - Watchtower - автообновление контейнеров (label-enable) для будущего автодеплоя backend.
4. Настроен .env со всеми доступами (БД, pgAdmin, реестр).
5. Создан пользователь реестра скриптом registry/create-user.sh (bcrypt-htpasswd).
6. Backend намеренно оставлен закомментированным - это часть 2 кейса.

Архитектура безопасности (по ТЗ)

- Внешний мир видит только Nginx по HTTPS; Postgres и pgAdmin наружу не торчат.
- Порты контейнеров забинжены на 127.0.0.1, системный Nginx проксирует их только через TLS (Let's Encrypt).
- Registry защищён авторизацией и отдаётся по HTTPS.
